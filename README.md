# @birklik/core

Общая предметная логика площадки [birklik.az](https://birklik.az). Её тянут **два**
приложения:

```
Birklik.az       сайт на Next.js
birklik-mobile   приложение на Expo
```

Смысл пакета один: правила работы площадки существуют **в одном экземпляре**. Как считается
срок платного тарифа, что показывать на витрине, а что прятать, как устроена бронь — всё это
не оформление, а поведение продукта. Разъедься оно между сайтом и приложением — получатся
два разных продукта с разными ошибками.

## Что здесь есть

```
src/types      что такое объявление, бронь, пользователь, уведомление
src/data       справочник 73 регионов, псевдонимы городов, фильтрация выдачи
src/utils      premium-helper (тарифы и сроки, с тестами), валидаторы, разбор ошибок
src/messages   переводы на три языка: az, en, ru
```

## Что здесь НЕ должно появиться

Всё, что знает про среду выполнения. Ни `document`, ни `window`, ни `AsyncStorage`, ни
работы с Firebase.

Причина в том, что пакеты Firebase у сайта и приложения **разные**: `firebase/firestore`
против `@react-native-firebase/firestore`. Код, который их зовёт, общим быть не может без
прослойки — поэтому `services` сюда пока не переехал, а `image-compression` не переедет
никогда: он работает через canvas браузера, а на телефоне ту же задачу решает
`expo-image-manipulator`.

Проверка простая: **если файл нельзя выполнить голым Node, ему здесь не место.**

## Как подключено

Обоими приложениями — через подмодуль git, в папку `core`. Так облачная сборка EAS видит
исходники: она забирает только свой репозиторий и содержимого соседних папок не знает.

Правка общей логики идёт в три шага: коммит здесь → обновление ссылки на подмодуль в
веб-репозитории → то же в мобильном. Пропустишь второй или третий — приложение соберётся со
старой версией и это не будет видно.
